PHASE 6C — FINAL RELIABILITY AND EDGE-CASE PASS

The UI is now visually polished.

DO NOT redesign the UI.

DO NOT add new features.

DO NOT change the current visual layout unless fixing an actual bug.

The goal of this phase is to make sure the existing application is reliable in real-world use.

==================================================
1. EDITOR INPUT
==================================================

Verify:

- Can always type immediately after opening.
- Cursor appears correctly.
- Enter creates a new line.
- Backspace works normally.
- Delete works normally.
- Arrow keys work.
- Home/End work.
- Page Up/Page Down work.
- Text selection works.
- Mouse selection works.
- Double-click word selection works.
- Triple-click/line selection behaves normally.

==================================================
2. SCROLLING
==================================================

Create a very long document.

Verify:

- Vertical scrolling works smoothly.
- Scroll wheel works.
- Trackpad scrolling works.
- Page Up/Page Down work.
- No horizontal scrolling appears.
- Long lines wrap correctly.
- Wrapped lines do not cause line-number corruption.

Do NOT modify the existing scrolling architecture unless an actual bug is found.

==================================================
3. LINE NUMBERS
==================================================

Verify with:

1 line
10 lines
100 lines
500 lines

Also test:

- empty lines
- consecutive empty lines
- long wrapped lines
- inserting lines in the middle
- deleting lines in the middle
- undo/redo
- scrolling

Line numbers must remain perfectly aligned with the corresponding text baseline.

Do NOT rewrite the line-number implementation.

==================================================
4. FORMATTING
==================================================

Test:

⌘B
⌘I
⌘Z
⇧⌘Z

Verify:

- Bold works.
- Italic works.
- Bold + italic works.
- Formatting can be undone.
- Formatting can be redone.
- Typing after formatted text behaves correctly.
- Formatting survives saving and reopening.

Do not change the formatting architecture.

==================================================
5. FIND
==================================================

Test:

⌘F
⌘G
⇧⌘G
Escape

Verify:

- Find opens correctly.
- Search field receives focus.
- Matching text is selected.
- Search works across multiple lines.
- Search works with formatted text.
- No matches are handled correctly.
- Search wraps around correctly.
- Escape returns focus to the editor.
- Find does not modify undo history.

==================================================
6. TXT IMPORT / EXPORT
==================================================

Test:

- Empty TXT file
- One-line TXT file
- Multi-line TXT file
- Very long TXT file
- UTF-8 text
- Unicode characters
- Emoji
- Windows CRLF line endings
- LF line endings

Verify imported content displays correctly.

Export the same content and verify the resulting TXT contains the expected plain text.

Do not modify the existing import/export architecture unless a real bug is found.

==================================================
7. PERSISTENCE
==================================================

Test:

1. Type content.
2. Apply formatting.
3. Quit using ⌘Q.
4. Relaunch.
5. Verify content is restored.
6. Verify formatting is restored.

Also test:

- Empty note
- Long note
- Rapid typing
- Multiple quit/relaunch cycles

Do NOT change the storage location.

Do NOT introduce a second storage system.

==================================================
8. MENU-BAR LIFECYCLE
==================================================

Verify:

- App launches correctly.
- Menu-bar icon appears.
- Clicking it opens the popover.
- Clicking outside behaves correctly.
- Reopening works.
- ⌘Q completely terminates the app.
- No orphan NotchPad process remains.
- Relaunch works normally.

==================================================
9. TXT DRAG & DROP
==================================================

Verify:

- Dragging a TXT file onto the editor works.
- Imported content appears correctly.
- Existing content is not silently destroyed if confirmation is required.
- Persistence works afterward.

==================================================
10. LIGHT / DARK MODE
==================================================

Test the application in:

- Light Mode
- Dark Mode

Verify:

- Text remains readable.
- Line numbers remain readable.
- Toolbar remains readable.
- Find remains readable.
- Status text remains readable.
- Editor background adapts correctly.
- No hard-coded colors look broken.

Do NOT redesign either theme.

==================================================
11. IMPORTANT VISUAL BUG CHECK
==================================================

Inspect the first-line editor area carefully.

There appears to be a strange rounded control/icon immediately before the text cursor in the current UI screenshot.

Determine whether this is:

- an intentional editor control,
- an accidental view,
- an NSTextView accessory,
- an input/formatting artifact,
- or another unintended UI element.

If it is NOT intentionally part of the design:

REMOVE/FIX ONLY THAT ARTIFACT.

Do not alter the surrounding editor layout.

==================================================
12. CRASH / FREEZE CHECK
==================================================

The application has previously experienced:

- freezes when pressing Enter
- crashes related to line numbers
- typing becoming disabled
- scrolling/layout problems

These issues are now believed to be fixed.

Explicitly test:

- typing continuously
- pressing Enter repeatedly
- holding Enter
- typing 100+ lines
- scrolling while typing
- formatting while typing
- Find while typing
- undo/redo repeatedly

The application must remain responsive.

==================================================
13. PERFORMANCE
==================================================

Do not optimize prematurely.

Only investigate if an actual performance issue appears.

The editor should remain responsive with at least several hundred lines of text.

==================================================
14. CRITICAL RULE

DO NOT refactor stable systems simply because they could be "cleaner."

If something works:

LEAVE IT ALONE.

Make the smallest possible changes only when a real bug is reproduced.

==================================================
FINAL VERIFICATION

Build the actual application.

Launch the actual built executable.

Perform the tests above.

Do not report success based only on compilation.

Report:

- bugs found
- bugs fixed
- files changed
- tests performed
- build result
- launch result
- whether any existing functionality was changed

If no bugs are found, make ZERO unnecessary code changes.

STOP AFTER THIS PHASE.

PHASE 4 — FIND TEXT ONLY

The editor is now stable.

DO NOT change the existing editor architecture.

Current functionality that MUST remain working:

- One-note editor
- 18pt font
- Text wrapping
- Vertical scrolling
- No horizontal scrolling
- Persistence
- Line numbers
- Correct line-number alignment
- Bold
- Italic
- ⌘B
- ⌘I
- ⌘Z
- ⇧⌘Z
- ⌘A
- ⌘C
- ⌘V
- ⌘X
- Enter/new lines

Implement ONLY a Find Text feature.

==================================================
OPENING FIND
==================================================

⌘F should open a small, clean native-looking Find UI.

It should NOT replace the editor.

The editor remains visible underneath.

Suggested appearance:

┌─────────────────────────────────────┐
│ 🔍 Find…                    2 of 7  │
└─────────────────────────────────────┘

Keep it compact and visually consistent with the existing app.

Do NOT create a separate window.

Do NOT create another editor.

==================================================
SEARCH BEHAVIOR
==================================================

Search the current note's text.

Search should happen LIVE as the user types.

Example:

Document:

Hello world
This is my world
Another line

Search:

world

Both matches should be found.

The current match should be visibly selected/highlighted using native NSTextView selection behavior.

Do NOT modify the actual text to highlight matches.

==================================================
KEYBOARD SHORTCUTS
==================================================

⌘F
→ Open Find.

⌘G
→ Find next.

⇧⌘G
→ Find previous.

Enter
→ Find next while Find UI is focused.

Shift + Enter
→ Find previous.

Escape
→ Close Find UI and return focus to the editor.

When Find closes, the editor should become first responder again.

==================================================
MATCH COUNTER
==================================================

Show:

"2 of 7"

meaning:

current match = 2
total matches = 7

If there are no matches:

"No matches"

If the search field is empty:

Do not show a match count.

The counter should update immediately as the search text changes.

==================================================
SEARCH RULES
==================================================

Default search behavior:

- Case-insensitive
- Search plain visible text
- Search across the entire current note
- Do not modify the stored text
- Do not modify formatting

Example:

Searching:

hello

should find:

Hello
HELLO
hello

==================================================
SELECTION / NAVIGATION
==================================================

When a match is found:

1. Select that match in the existing NSTextView.
2. Scroll the editor so the match is visible.
3. Keep the existing cursor/selection behavior intact.

Pressing ⌘G should move:

match 1
→ match 2
→ match 3
→ ...
→ match N
→ match 1

Likewise, ⇧⌘G should move backwards.

If the match is below the current viewport, the existing vertical scrolling system should automatically reveal it.

DO NOT implement custom scrolling.

Use the existing NSTextView selection and scrolling APIs.

==================================================
FORMATTING
==================================================

Find must work with formatted text.

For example:

Hello WORLD

If "WORLD" is bold, searching "world" must still find it.

Do NOT remove or modify bold/italic attributes.

Do NOT change formatting when selecting a match.

==================================================
UNDO / REDO
==================================================

Searching must NOT create undo operations.

Opening Find must NOT create an undo operation.

Moving between search results must NOT create undo operations.

Closing Find must NOT create an undo operation.

The existing undo/redo stack must remain unchanged.

==================================================
PERSISTENCE
==================================================

Find must NOT affect persistence.

Searching must NOT trigger a document save.

Selecting a search result must NOT modify the stored document.

==================================================
IMPORTANT UI BEHAVIOR
==================================================

When ⌘F is pressed:

- Find UI appears.
- Search field automatically receives focus.
- Existing editor text remains unchanged.

When Escape is pressed:

- Find UI disappears.
- Editor regains first responder.
- Existing selection/cursor state is restored as naturally as possible.

Do NOT steal focus permanently from the editor.

==================================================
EDGE CASES
==================================================

Handle:

- Empty document
- Empty search
- No matches
- One match
- Multiple matches
- Search text longer than document
- Search while scrolled to bottom
- Search while text is formatted
- Search after editing the document
- Search after pressing Enter
- Search after undo/redo
- Closing and reopening Find

If the document changes while Find is open, refresh the match results.

==================================================
DO NOT IMPLEMENT
==================================================

Do NOT add:

- Replace
- Replace All
- Regular expressions
- Case-sensitive toggle
- Whole-word toggle
- Search history
- Fuzzy search
- Multiple notes search
- File search

Keep Find deliberately simple.

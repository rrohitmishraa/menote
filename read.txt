# NOTCHPAD — COMPLETE PRODUCT & ENGINEERING SPECIFICATION

Build a polished, lightweight, native **macOS scratchpad application** called **NotchPad**.

NotchPad is a personal, always-available scratchpad designed for capturing thoughts, code, links, images, snippets, tasks, and temporary information with as little friction as possible.

The core philosophy is:

> **Think → Open → Type/Paste → Automatically Saved → Collapse**

The interface should disappear/collapse when dismissed, but **the note must NEVER be deleted simply because the interface closes**.

NotchPad should feel like a small, elegant extension of macOS rather than a conventional notes application.

The goal is not to build the application with the most features.

The goal is to build:

> **The fastest, cleanest, most useful local scratchpad for Mac.**

# 1. PRODUCT PRINCIPLES

The application must prioritize:

1. Speed
2. Simplicity
3. Native macOS behavior
4. Excellent keyboard interaction
5. Local-first storage
6. Privacy
7. Data ownership
8. Reliability
9. Beautiful minimal design
10. Useful features without feature bloat

Do NOT turn this into:

* Notion
* Evernote
* Obsidian
* Todoist
* Raycast

* A project-management application
* A full IDE
* A calendar
* A collaboration tool
* An AI workspace

NotchPad should remain a **scratchpad first**.

---

# 69. CRITICAL ARCHITECTURE RULE

Do not make Access Point determine application architecture.

Bad:

```text
Notch App
Menu Bar App
Separate Storage
Separate Notes
```

Correct:

```text
                 Notch
                   │
Menu Bar ─── NotchPad Core ─── Keyboard
                   │
               NoteStore
                   │
          Persistence Layer
                   │
         Local Data Directory
```

The UI is interchangeable.

The application state is shared.

The data is shared.

---

# 70. STORAGE ARCHITECTURE

The selected storage directory is the source of truth.

For example:

```text
NotchPad/
├── notes.json
├── clipboard.json
├── metadata.json
├── images/
└── attachments/
```

Do not scatter persistent user data unnecessarily across unrelated directories.

The application may store OS-level preferences separately if necessary, but user content should live inside the selected NotchPad storage directory.
